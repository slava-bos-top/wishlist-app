## Безпека (практикум 15)

### Знайдені вразливості

1. **XSS через href (поле `url`).** Поле `type="url"` приймає схему `javascript:`.
   Значення `javascript:alert('XSS')` потрапляло в `<a href>` на сторінці деталей,
   і клік по посиланню виконував код. React 18 лише виводить попередження в консоль.
2. **Поле `title`.** Не вразливе: застосунок написаний на React, який екранує текст
   у JSX. `innerHTML` і `dangerouslySetInnerHTML` не використовуються. Тестовий рядок
   `<img src=x onerror="alert('XSS')">` відображається як текст.

### Виправлення

- Функція `getSafeUrl()` дозволяє лише схеми `http:` і `https:`
  (через `new URL()`, що нормалізує обхідні записи на кшталт `JaVaScRiPt:`).
- Перевірка при додаванні бажання (форма відхиляє небезпечний URL).
- Перевірка при відображенні: захищає і від підміни даних у localStorage/IndexedDB.
- Посилання відкривається з `rel="noopener noreferrer"`.

### Сховища

У localStorage та IndexedDB зберігаються лише назва, ціна, накопичена сума, пріоритет,
статус і посилання. Паролів і токенів немає. Дані сховища вважаються недовіреними
(їх може змінити користувач чи стороннiй скрипт), тому url перевіряється при кожному рендері.
